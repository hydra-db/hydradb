# ISO GQL conformance of the experimental engine

The experimental engine reads ISO/IEC 39075:2024 GQL, as amended by Technical
Corrigendum 1:2026, through the same Cypher 25 front end it uses for Cypher.
This document records what it claims, what it executes, where it deviates, and
what is still missing. The design behind it is [`design.md`](design.md), the
per-feature status is [`features.md`](features.md), every difference from the
books in one list is [`deviations.md`](deviations.md), and
[`AGENTS.md`](AGENTS.md) explains how to contribute.

The complete test map is
[`../shared/tests/README.md`](../shared/tests/README.md). Cargo-owned tests live
outside production crates. Public-protocol and observability harnesses live in
[`../shared/scripts/`](../shared/scripts/).

The standard and the corrigendum are the ground truth. Neo4j's GQL appendix is
used only to keep Cypher behaviour that already works from changing.

## How it is built

| Level | Where | What it does |
|---|---|---|
| Parser | Neo4j's Cypher 25 snapshot in `query-language/cypher/grammar/` plus the GQL overlay in `query-language/gql/overlays/`, as `crates/cypher-parser-antlr/build.rs` compiles them, and `crates/cypher-parser-antlr/src/lower.rs` | The ANTLR tree is lowered by walking the generated contexts. Precedence, comments, escapes and keywords are the grammar's. A construct is typed only once the engine executes it; anything else stays an untyped fragment naming the clause it stopped in. |
| Semantics | `crates/cypher-engine/src/plan/lower.rs` | Scope and reference checks (`42002`), Syntax Rule violations (`42000`), `EXISTS` correlation, label expressions, truth tests. |
| Execution | `crates/cypher-engine/src/execute.rs`, `src/execute/functions.rs` | Numeric, string, boolean and predicate semantics of Clauses 19 and 20; the `EXISTS` mark join; `01G11` on null elimination. |
| Diagnostics | `crates/cypher-ast/src/status.rs`, `EngineError::status_object`, `ExecutionOutcome` | Table 8 GQLSTATUS codes, §4.9.2 standard descriptions, §4.9.3 precedence, and §23.2 diagnostic records, which are optional feature GA08 (`OPERATION`, `OPERATION_CODE`, `CURRENT_SCHEMA`, `INVALID_REFERENCE`, `_classification`). |

## Minimum conformance claims (§24.2 as amended)

- **GC00, automatic graph population.** The engine reads a graph that already
  exists in its schema. Corrigendum 1 makes GC00 or GC04 the required claim.
- **Unicode 17.0.0** for normalization (`unicode-normalization` 0.1.25).
  Identifier character classes are the grammar's (Neo4j's `LETTER` and
  `PART_LETTER`).
- **Property value types:**
  - STRING
  - BOOLEAN
  - INTEGER: 64-bit signed. An arithmetic result or sum outside that range
    raises `22003`. Integer literals may also use the UINT64 range:
    decimal literals accept at most 20 digits, and integer literal values
    may range from -2^63 through 2^64 - 1. A literal outside the supported
    exact range raises `42000`.
  - FLOAT: IEEE 754 binary64. GA01 is not claimed, so arithmetic never yields
    an infinity or NaN: such a result raises `22003`, and a zero divisor
    raises `22012`.

## What is supported

[`features.md`](features.md) is the full matrix: every mandatory construct and
all 234 optional features, each with its parser, semantics, execution and
diagnostics status, and a summary of what runs and what does not. It is
generated by `query-language/gql/tests/engine/gql_features.rs` from probe queries
run against the engine, so it is always current; this document does not
repeat its counts. [`AGENTS.md`](AGENTS.md) explains how to add a feature and
its tests.

The mandatory rows come from the standard's grammar, not from what the engine
supports. Every production that minimum conformance allows is listed in
`query-language/gql/tests/engine/gql_features/grammar.rs` with the one row that
covers it, and the matrix ends with that list.

Each level is checked against the books, not just exercised:

- **Execution** is ✅ only when a row's probe returns the answer the
  standard's General Rules give, worked out by hand from the test graph.
- **Diagnostics** comes from the rules ledger,
  `query-language/gql/tests/engine/gql_features/rules.rs`. That ledger lists every
  Syntax Rule restriction and every raised condition in Clauses 6 to 23,
  mandatory and optional, and says for each whether a conformance test pins
  it, the engine also accepts text it forbids (an extension), it is a
  deviation, it cannot arise here, it is a gap, or its feature does not run
  yet (pending). Every row that runs, mandatory or optional,
  must have its rules in the ledger, and none of them may be pending.

`WITH` and `LET` (GQ09) items support `EXISTS` and `VALUE { }` subqueries,
correlated with the incoming row, as `RETURN` items do. Standalone
`ORDER BY` (§14.9) is not a projection boundary: its subqueries read the
incoming scope. Primitive `RETURN` sort keys still exclude nested query
specifications (§14.10 SR 4). A subquery inside a `LET ... IN ... END`
expression's body remains unsupported (L24 in [`deviations.md`](deviations.md)).

## What the books make optional

Reading the Conformance Rules literally puts some constructs outside minimum
conformance that are easy to take for mandatory:

| Construct | Why it is optional |
|---|---|
| `SELECT` | The grammar has `<select statement>` only inside `<focused linear query statement>`, which §14.3 gates behind GQ01 (`USE`), with or without a `USE` clause |
| `EXISTS { MATCH … }` with no `RETURN` | The braces hold a `<match statement block>`, which §19.4 gates behind GQ22 even for one `MATCH`; `EXISTS { MATCH … RETURN … }` is mandatory |
| `OPTIONAL { MATCH … }` | §14.4 gates any `<match statement block>` after `OPTIONAL` behind GQ21 |
| `FOR` | Its source is a list (GQ10) or a binding table (GQ23) |
| Sort keys other than a variable | §14.10 and §14.12 gate them behind GQ14, so `ORDER BY i.score` needs it and `ORDER BY s` does not |
| `1.5` | A decimal without an exponent is an exact numeric literal, gated behind GL04; mandatory GQL writes `1.5E0` |
| `INSERT`, `SET`, `REMOVE`, `DELETE` | GD01; §13.1 Syntax Rule 5 makes a data-modifying statement contain one |
| Session and transaction commands | After Corrigendum 1 every `SESSION SET`, `SESSION RESET` and `SESSION CLOSE` form has a feature (GS01 to GS18), and `START TRANSACTION`, `COMMIT` and `ROLLBACK` need GT01. A request still runs in a transaction the implementation starts and ends |
| `TEMP`, `NO BINDINGS` | Specification devices the standard uses internally; no conforming query contains them |
| Byte strings | Mandatory syntax can concatenate or take `LEFT`/`RIGHT` of a byte string, but only GV35 can make one

## Where the text needs a reading

Five passages, read literally, contradict the rules around them. The engine
follows the reading those rules require.

- **Aggregation without `GROUP BY`** (§14.11 General Rule 3 b). With no
  `GROUP BY`, each return item is evaluated for each incoming record in a new
  child execution context, whose working table §4.8.2 sets to a unit binding
  table. Read literally, `MATCH (i:Item) RETURN count(*) AS c` would then
  return one row for each item, each counting 1. Two other rules assume it
  aggregates the whole table instead. §14.10 Syntax Rule 4 treats such a
  return like `DISTINCT`, limiting its sort keys to return items. §14.12
  Syntax Rule 12 rewrites `SELECT … GROUP BY ()` into a return with no
  `GROUP BY`, which is right only if the two agree. Minimum conformance would
  otherwise have no way to aggregate a table at all, since `GROUP BY` needs
  GQ15. So a return with no `GROUP BY` whose items all aggregate gives one row
  over the whole working table, as `GROUP BY ()` would. §20.6 Syntax Rule
  10 b) agrees: it admits a `VALUE` subquery as having one row when its one
  return item aggregates without `GROUP BY`. Items that do not
  aggregate beside ones that do are non-conformance N5 in
  [`deviations.md`](deviations.md).
- **An override inside a negation or a conjunction** (§16.12 Syntax Rules 1
  and 4). Neither rule forbids it, so `-/!(<R)/->` and `-/R & <S/->` seem to
  pass. Syntax Rule 6 b) iv) and viii) then make the negation or conjunction
  a label expression, which cannot hold an override, and NOTEs 255 and 257
  say no such operator can arise there. The engine rejects this at semantic
  validation (`42000`), as it rejects the forms Syntax Rules 1 to 4 forbid.
- **A cast of a Boolean or temporal value to a string** (§20.8 General Rule
  4 j) iv) 2) C) and v) 2) C)). Each case builds the literal `Y` and checks
  its length, then says "TV is SV", which would give the Boolean or temporal
  value itself as the string result. The cases for numbers say "TV is Y", and
  the declared type of the cast is the string type, so the engine reads these
  the same way: `CAST(true AS STRING)` is `'TRUE'`.
- **The units of `DURATION_BETWEEN`** (§20.28 General Rule 5 d) iv)). Read
  literally, two datetimes are measured in days, as two dates are, so the
  day and time-based result of two datetimes an hour apart would be zero.
  Syntax Rule 3 e) makes that result a day and time-based duration, which
  holds hours and seconds; the engine measures dates in days and datetimes
  and times in nanoseconds.
- **Casts between temporal instant types** (§20.8 General Rule 4 k) iii),
  l) iii) to v), n) vi)). These descriptions use fixed character counts that
  do not fit every accepted temporal spelling (8 characters for a date,
  which has 10). The engine extracts typed fields instead. A cast from a
  zoned datetime to `LOCAL DATETIME` adds the source displacement using
  checked arithmetic, following n) vi): `CAST(DATETIME
  '2026-01-02T03:04+05:00' AS LOCAL DATETIME)` is `2026-01-02T08:04`, not
  `2026-01-02T03:04`. A local-to-zoned cast retains the local fields and
  associates the current displacement. These are the implemented
  cast-specific rules, not a claim that removing a zone preserves the
  source's clock time for every temporal target.

## Differences from the books

The engine runs one language, GQL and Cypher 25 together.
[`deviations.md`](deviations.md) lists every difference and the decision for
each; in short:

- **Five non-conformances.** A conforming GQL query gets another answer,
  kept because Cypher users rely on it (§24.5.3):

  | Conforming query | GQL | The engine |
  |---|---|---|
  | A comparison whose values cannot be compared at runtime, e.g. `n.x = 1` with `n.x` a string | `22G04` | Null |
  | `DISTINCT`, `UNION`, `EXCEPT` or `INTERSECT` over values that cannot be compared | `22G04` | The values are distinct |
  | `MAX` or `MIN` over values that cannot be compared | `22G04` | The extreme in the engine's order of types (US007) |
  | `sum()` over no values | Null | `0` |
  | Items that do not aggregate beside ones that do, with no `GROUP BY`, e.g. `RETURN i.kind AS k, count(*) AS c` | Not grouped by `k` | One row per `k` (Cypher's implicit grouping) |

  And one GQLSTATUS detail: a runtime-incomparable `TRIM` character raises
  `22G03`, not `22G04` (GF05, GF06).

- **Extensions.** The engine also accepts language GQL rejects, with Cypher's
  meaning, as §5.3.2.3 (IE005) allows: reserved words as names, items without
  `AS`, Cypher's `-->`, `1--1`, unknown escapes,
  backtick-quoted variables, operands of the wrong static type (which fail
  while running, with `22G03`), and the others in
  [`deviations.md`](deviations.md). A conforming query never meets one.

- **`n.id`** is a property: every node has a property `id` whose value is
  its identity, which is HydraDB's data model. An edge's `id` is an ordinary
  stored property.

Constructs the engine did not execute before follow the standard even where
Neo4j differs. `TRIM` removes spaces only, not every whitespace character
(§20.24). `log(b, x)` is GQL's general logarithm; Cypher's one-argument
`log(x)` remains the natural logarithm. `XOR` shares the level of `OR`
(§20.20), so `a OR b XOR c` is `(a OR b) XOR c`, where Neo4j binds `XOR`
tighter. An unquoted `e IS DIRECTED` is the directed predicate (§19.8), as an
unquoted `x IS TRUE` is the truth test; a backticked `` e IS `DIRECTED` ``
stays a label test. `STDDEV_SAMP` over one value is null (§20.9), where
Neo4j's `stDev` answers `0`.

## Implementation-defined choices

| Item | Choice |
|---|---|
| ID086 default match mode | DIFFERENT EDGES |
| IE005 language that breaks a Syntax Rule | Accepted with Cypher's meaning where Cypher has one (the extensions above); refused otherwise |
| US007 order of values that cannot be compared | By type, then by value, as Cypher orders them |
| ID028 precision of the binary exact numeric types | INT, INTEGER and BIGINT 64-bit signed (precision 63), SMALLINT 16-bit signed, USMALLINT 16 bits, UBIGINT 64 bits; `INT(p)` and `UINT(p)` declare `p` bits, but runtime values remain limited to INT64 through UINT64 (L20), not the full declared wider range |
| ID037 precision and scale of the approximate numeric types | FLOAT and DOUBLE use binary64 (FLOAT64), REAL binary32 (FLOAT32); `FLOAT(p, s)` chooses the narrowest declared format from FLOAT16 to FLOAT256, but FLOAT128 and FLOAT256 currently use binary64 storage, not the declared wider precision |
| IL011 maximum precision and scale | Accepted declarations: 256 binary exact bits, 38 decimal digits, approximate precision 236 and scale 18; the binary limits are declaration limits, not verified full-width runtime support (see Open work) |
| ID034 decimal precision | 38 digits; `DECIMAL` alone is `DECIMAL(38, 0)` |
| ID065, ID066, ID067 precision and scale of exact arithmetic | 38 digits; a sum or difference has the larger scale, a product the sum of the scales, a quotient the larger scale plus 6, at most 38 |
| IA011 rounding of exact arithmetic | To the result's scale, a half away from zero |
| ID023 preferred name of byte string types | `BINARY(n)` for a fixed length, `BYTES` otherwise |
| IV008 normal forms of value types | The preferred names `EXPLAIN` shows: `INT8` to `INT256`, `UINT8` to `UINT256`, `INT(p)`, `FLOAT16` to `FLOAT256`, `STRING`, `CHAR(n)`, `STRING(min, max)`, `LIST<T>[n]`, `ANY<…>` |
| IV011 dynamic property value type | `ANY<BOOLEAN \| INTEGER \| FLOAT \| STRING>`, the property value types claimed above |
| IV023 truncating whitespace | Unicode's White_Space characters |
| IL024 fractional seconds precision | 9 digits, nanoseconds |
| SQL interval precisions (GL12; ISO/IEC 9075-2 §10.1) | A leading field of at most 18 digits, two when none is written; fractional seconds of at most 9, six when none is written |
| ID048 default time zone displacement | UTC; there is no session time zone (GS15 is not claimed), so it is the current displacement throughout |
| US009 when the request timestamp is set | When the request's parameters are bound, before it runs; every current date and time function of the request reads the same instant |
| IA026 whether `DURATION_BETWEEN` reflects leap seconds | It does not: a day is 86,400 seconds |
| Exact division | `INT / INT` truncates toward zero; `%` keeps the dividend's sign |
| IA015 string comparison | Unicode code point order, no padding |
| IW017 concatenation of unnormalized strings | The plain concatenation; two NFC inputs give an NFC result |
| IW014 visually confusable identifiers | Never determined (permitted by §4.16.3), so `42004` is never raised |
| IL013 maximum string length | Bounded only by memory, so no string condition `22001` arises |
| IL010 digits in an integer literal | Up to 20 decimal digits, when a supported exact type holds the value (INT64 through UINT64) |
| IL015 maximum list length, and of a path's element list | Bounded only by memory; declared list lengths still enforce `2202F` on truncation |
| IL018 maximum upper bound of a graph pattern quantifier | 255 |
| IA013 whether a selective path search stops at an exception | It stops: the first exception a candidate raises fails the query |
| ID061, IV015 `SESSION_USER` | The transport principal as a string: `bearer:sha256:<hash of the token>`, `mtls:<certificate fingerprint>`, or `insecure`; `anonymous` for an engine given no session |
| ID062 type of a `LIMIT` or `OFFSET` value | INTEGER |
| ID057, ID058 type of a `FOR` ordinality or offset | INTEGER |
| IS001 null ordering | Nulls sort after every value: last ascending, first descending, in every sort. An explicit `NULLS FIRST` or `NULLS LAST` (GA03) places them whatever the direction |
| ID076 type of `ELEMENT_ID` | STRING: `node:` and the node's `id`, or `edge:` and the edge's internal identity |
| ID079 type of an unsuffixed approximate literal; the regular (`F`) and double (`D`) approximate types | FLOAT, IEEE 754 binary64, for all three |
| IA005 rounding or truncation | `PERCENTILE_DISC` at a fractional position rounds to the nearest position, a half upwards; a `CAST` to an exact numeric type rounds to the nearest integer, a half away from zero; a duration multiplied or divided rounds to the nearest month or nanosecond, a half away from zero; `DURATION_BETWEEN ... YEAR TO MONTH` counts the whole calendar months, truncating; a date plus a day and time-based duration moves by its whole days |
| IV002 order of two records | In a sort, by their field names, then their fields' values in name order |
| IA014 a `NULL` whose type cannot be determined | Not an error; it has the null type |
| IA019 bidirectional control characters in strings and comments | Allowed |
| Valid syntax that is not executed | `0A000` feature not supported, the ISO/IEC 9075 condition GQL leaves to other standards |
| Storage, limit and cancellation failures | `50000`, an implementation-defined class |

## GQLSTATUS mapping

| Situation | GQLSTATUS |
|---|---|
| Rows returned | `00000` |
| `FINISH`, whose result is omitted | `00001` |
| No rows | `02000` (outranks a warning, which moves to the additional status objects) |
| An aggregate skipped a null | `01G11` |
| Text that does not parse | `42001` |
| A name that is not in scope, or a parameter the request did not supply | `42002`, with `INVALID_REFERENCE` in the diagnostic record |
| A Syntax Rule violation, e.g. two result columns with one name, `RETURN *` with nothing in scope or with `GROUP BY`, an aggregate outside a projection item or inside another aggregate, a node and an edge variable with one name, `UNION` arms with different columns, a literal outside its type, a property of a property | `42000` |
| An INTEGER result outside 64 bits, float overflow, `EXP` overflow | `22003` |
| Division or `MOD` by zero | `22012` |
| `LEFT`/`RIGHT` with a negative length | `22011` |
| A `TRIM` character that is not one character | `22027` |
| `LN` of a non-positive number | `2201E` |
| `POWER`/`SQRT` outside its domain | `2201F` |
| `LOG`/`LOG10` outside its domain | `2201Z` (Cor 1) |
| `ACOS`/`ASIN` outside [-1, 1] | `2202M` (Cor 1) |
| `LIMIT`/`OFFSET` negative | `22G02` |
| `LIMIT`/`OFFSET` not an integer, an operand of the wrong type | `22G03` |
| `LIMIT`/`OFFSET` null, or a null where none is allowed (a seek key, an argument of `ALL_DIFFERENT` or `SAME`) | `22004` |
| `ALL_DIFFERENT` or `SAME` over a node and an edge | `22G04` |
| A `PERCENTILE_CONT` or `PERCENTILE_DISC` fraction outside [0, 1], which names no position and for which the standard defines neither a result nor a condition | `22000`, data exception with no subclass (§23.1) |

`01G11` reaches the outcome through `GraphRead::raise_completion_condition`. The
HydraDB shard adapter and the test storage keep these conditions; a backend
that does not implement the hook reports plain success.

### On the wire

The server sends the GQL-status objects of experimental-engine queries to
clients (IW007 leaves the manner implementation-defined):

| Transport | Failure | Success |
|---|---|---|
| Bolt | FAILURE keeps `code` and `message` and adds Bolt 5.7's `gql_status`, `description`, `neo4j_code` and `diagnostic_record` | The final SUCCESS adds Bolt 5.6's `statuses`: `gql_status`, `status_description`, `diagnostic_record` each |
| HTTP | The error body adds `gql_status`, `description` and `diagnostic_record` beside `code` and `message`; so does an NDJSON `error` line | The response body, or the NDJSON `summary` line, adds `statuses` |
| Query transport | A routed failure carries the object in `gql`, so a client on another node sees the owner's GQLSTATUS | Result sets and pages carry `statuses` |

A path value (G004, GV55) is sent as a Bolt path structure and an HTTP path
object, every node and edge with its labels or type and properties, as the
native path procedures send theirs. A record (GV45) is sent as a Bolt map and
as an HTTP value of type `record` whose value is a JSON object, one member
for each field. A temporal value goes as the Bolt date, time, local time,
datetime, local datetime or duration structure, and as an HTTP value of type
`date`, `local_time`, `zoned_time`, `local_datetime`, `zoned_datetime` or
`duration` whose value is its ISO 8601 string. A decimal goes as its exact literal, a Bolt string and an HTTP value of type `decimal`; a byte string as Bolt bytes and an HTTP value of type `bytes` in hexadecimal.

Every field is optional, so an older peer or a driver of an older Bolt
version ignores it. The server negotiates Bolt 5.1 to 5.4, so official drivers
do not yet surface these fields in their APIs; clients that read the metadata
do. The legacy OpenCypher executor reports no GQL-status objects.

## Open work

- **Wide numeric representations:** accepted INT256, FLOAT128 and FLOAT256
  declarations do not establish full-width values, arithmetic, casts,
  comparison, hashing, parameters or serialization. Integers retain L20's
  runtime range; wide floats retain binary64 storage. Full-width support or
  explicit rejection of unsupported declarations needs a representation and
  support-boundary decision; no full-width conformance is claimed here.
- **Grammar:** the GQL overlay (`query-language/gql/overlays/`)
  adds what minimum conformance needs, and the optional syntax the engine can
  run (G002, G006, G007, G012, G044, G112, GA03, `<->`, GL03, GL11, GQ02, GQ04 to GQ07, GQ11, GQ18, GQ21, GQ24). Optional syntax the engine cannot run is
  left out, since a feature that is not claimed is not part of the language.
  `--` comments (GB02) cannot be added: Cypher reads `--` as an edge.
- **Bolt 5.6 and 5.7:** negotiate them, so official drivers expose the
  GQL-status objects the server already sends.
- **Parse error positions:** `42001` reports no line or column, because the
  runtime's validated parse returns only error counts.
- **`NEXT` (GQ20):** a returned table is passed through a scope boundary;
  an omitted result (`FINISH`) executes before the continuation starts on a
  unit table. Still refused inside a subquery, whose enclosing names the
  table projection would hide, and inside or around a composite query.
- **Lists (GV50):** `||` on lists and `TRIM(list, n)` are not implemented.
- **Data modification (GD01 to GD04):** `INSERT`, `SET`, `REMOVE` and
  `DELETE` run on the transactional OpenCypher executor, not this engine,
  which is why the matrix shows them refused with `0A000`.
